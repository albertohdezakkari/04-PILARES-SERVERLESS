Ver y explorar las tablas en el diseñador

Descargad el modelo de Festival Check-in y abrid DynamoDB Data Modeler. En ☰ → Load from File, elegid el JSON. Usad el icono de cambiar tabla para pasar de Events a Registrations.

En Registrations, pulsad los prismáticos y seleccionad Define new query. Dadle un nombre, elegid la tabla Registrations y escribid evt-001 en Partition Key Value. Los dos registros comparten PK y tienen distinto userId. El atributo checkedInAt aparece en el registro con entrada. Para buscar por usuario en todos los eventos haría falta otro patrón de acceso.

El diseñador muestra la clave de Events, pero su visor omite las filas de tablas sin SK. Este es el registro de Events incluido en el modelo.

Los registros del diseñador son ejemplos. En el laboratorio empezamos con el evento y la tabla de inscripciones vacía.

  1. En DynamoDB → Tables → Create table, cread equipo-01-events. Escribid eventId en Partition key y elegid String. Dejad Sort key vacío y conservad la configuración predeterminada.
  2. Repetid con equipo-01-registrations. Usad eventId como Partition key y userId como Sort key, ambos String. Cambiad equipo-01 en ambos nombres por vuestro prefijo. Anotad los nombres exactos para la fase Lectura.
  3. Cuando Events esté Active, abrid Explore table items → Create item. En la vista de formulario, dad a eventId el valor evt-001. Con Add new attribute → String, añadid title con el valor Festival de otoño. Pulsad Create item.

title se añade al crear el registro. Los atributos registeredAt y checkedInAt se escribirán desde Lambda en sus respectivas fases.

Leer antes de escribir

  1. Cread una Lambda Node.js 22 en la misma región. Elegid el rol de ejecución autorizado por el laboratorio. Configurad las variables EVENTS_TABLE y REGISTRATIONS_TABLE con los nombres exactos.
  2. En index.mjs, añadid los imports y el esqueleto de trabajo que aparece abajo. Guardad y pulsad Deploy después de cada fase.
  3. Completad getPass con el profesor. Leed Events por eventId y Registrations por la pareja eventId + userId. Para estas pruebas, usad lectura consistente. Devolved 404 si no existe el evento.
  4. Cread una HTTP API con etapa $default, integración Lambda y formato de carga 2.0. Añadid GET /events/{eventId}/registrations/{userId} y conectad la integración.
  5. En CORS configurad el origen https://albertohdezakkari.github.io, métodos GET, POST, PATCH y cabecera Content-Type. Copiad la URL de invocación en la pantalla.

export async function handler(event) {
  const { eventId, userId } = event.pathParameters ?? {};
  const method = event.requestContext?.http?.method;
  if (eventId !== 'evt-001' || !/^equipo-\d{2}$/.test(userId ?? '')) {
    return json(400, { message: 'Usa evt-001 y un código equipo-00 a equipo-99' });
  }

  const key = { eventId, userId };
  try {
    if (method === 'GET') return await getPass(key);
    if (method === 'POST') return await register(key);
    if (method === 'PATCH') return await checkIn(key);
    return json(405, { message: 'Método no permitido' });
  } catch (error) {
    if (error.name === 'ConditionalCheckFailedException') {
      return json(409, { message: 'La operación no se puede aplicar a este estado' });
    }
    console.error(error.name, error.message);
    return json(500, { message: 'Revisa los logs de la función' });
  }
}

Antes de avanzar: la pantalla muestra el título real y «Sin inscripción».

Una inscripción por pareja de claves

  1. Completad register. Comprobad que existe el evento y guardad un ítem con ambas claves y registeredAt en UTC, asignado en Lambda.
  2. Condicionad el PutCommand a que no exista el ítem. Devolved 201 con un JSON de confirmación. La condición fallida se transforma en 409 en el esqueleto.
  3. Añadid POST /events/{eventId}/registrations/{userId} a la misma integración.

Antes de avanzar: pulsad Inscribirse dos veces. La primera devuelve 201 y la segunda 409. En DynamoDB hay un solo ítem para el equipo y la hora original se conserva.

Registrar la entrada

  1. Completad checkIn con UpdateCommand. Añadid checkedInAt en UTC. La condición exige una inscripción existente y que todavía no tenga checkedInAt.
  2. Devolved 200 con un JSON de confirmación. Añadid PATCH /events/{eventId}/registrations/{userId} a la API.
  3. Probad con un código nuevo y después con el código que sí se inscribió.

Antes de avanzar: un código nuevo recibe 409 y no crea un ítem. El inscrito recibe 200 y conserva ambas horas. Repetir la entrada devuelve 409.
