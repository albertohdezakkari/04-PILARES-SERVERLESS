Conectar con AWS Academy

Abre el laboratorio

En Git Bash (Windows) o Terminal (Mac), comprueba que tienes la herramienta.

Antes de avanzar El archivo ~/.aws/credentials está abierto dentro de la terminal.

Pega el bloque y guarda

En vi, escribe :set paste y pulsa Intro. Pulsa i para editar y pega el bloque completo de AWS Details. Para guardar y volver a la terminal, pulsa Esc, escribe :wq y pulsa Intro. Estas son las líneas que debes reconocer:

Si ya usas [default] para otra cuenta, guarda el bloque del laboratorio con la cabecera [academy]. Si ya tienes un perfil del laboratorio, reemplaza sus tres valores juntos.

Antes de avanzar Comprueba que el archivo guardado contiene una cabecera ([default] o [academy]) y los tres campos del laboratorio debajo.

Describe la infraestructura en serverless.yml

Desde la carpeta festival-checkin, ejecuta este comando para crear y abrir serverless.yml.

touch serverless.yml && vi serverless.yml

En la caja de abajo, pulsa Copiar archivo completo. En vi, escribe :set paste y pulsa Intro. Si el archivo está vacío, pulsa i y pega el contenido. Si ya contiene el archivo de este paso, compruébalo y sigue. Para guardar, pulsa Esc, escribe :wq y pulsa Intro.

En functions están las tres rutas y el archivo que las atiende. En resources busca las dos tablas: S significa texto, HASH es la PK y RANGE es la SK.

service: festival-checkin-${env:STUDENT_CODE}
frameworkVersion: ~4.45.0

provider:
  name: aws
  runtime: nodejs22.x
  region: ${env:AWS_REGION}
  stage: dev
  iam:
    role: ${env:LAMBDA_ROLE_ARN}
  environment:
    EVENTS_TABLE:
      Ref: EventsTable
    REGISTRATIONS_TABLE:
      Ref: RegistrationsTable
  httpApi:
    payload: '2.0'
    cors:
      allowedOrigins:
        - https://albertohdezakkari.github.io
      allowedHeaders:
        - Content-Type
      allowedMethods:
        - GET
        - POST
        - PATCH

build:
  esbuild: false

functions:
  checkin:
    handler: index.handler
    events:
      - httpApi:
          method: GET
          path: /events/{eventId}/registrations/{userId}
      - httpApi:
          method: POST
          path: /events/{eventId}/registrations/{userId}
      - httpApi:
          method: PATCH
          path: /events/{eventId}/registrations/{userId}

resources:
  Resources:
    EventsTable:
      Type: AWS::DynamoDB::Table
      Properties:
        BillingMode: PAY_PER_REQUEST
        AttributeDefinitions:
          - AttributeName: eventId
            AttributeType: S
        KeySchema:
          - AttributeName: eventId
            KeyType: HASH
    RegistrationsTable:
      Type: AWS::DynamoDB::Table
      Properties:
        BillingMode: PAY_PER_REQUEST
        AttributeDefinitions:
          - AttributeName: eventId
            AttributeType: S
          - AttributeName: userId
            AttributeType: S
        KeySchema:
          - AttributeName: eventId
            KeyType: HASH
          - AttributeName: userId
            KeyType: RANGE
  Outputs:
    EventsTableName:
      Value:
        Ref: EventsTable
    RegistrationsTableName:
      Value:
        Ref: RegistrationsTable

En provider.environment, cada Ref pasa a Lambda el nombre real de la tabla que crea CloudFormation. En Outputs vuelves a usar esas referencias para obtener los nombres desde la terminal.

ls -l serverless.yml
sed -n '1,18p' serverless.yml

Antes de avanzar ls muestra serverless.yml y su primera línea conserva ${env:STUDENT_CODE}. En KeySchema, comprueba que las dos tablas tienen eventId como HASH y que solo RegistrationsTable añade userId como RANGE. En environment, comprueba que cada Ref apunta a su tabla.

El handler recibe la petición y elige la operación. Por ahora cada operación responde 501 hasta que la construyas.

import { DynamoDBClient } from '@aws-sdk/client-dynamodb';
import {
  DynamoDBDocumentClient, GetCommand, PutCommand, UpdateCommand
} from '@aws-sdk/lib-dynamodb';

const db = DynamoDBDocumentClient.from(new DynamoDBClient({}));
const eventsTable = process.env.EVENTS_TABLE;
const registrationsTable = process.env.REGISTRATIONS_TABLE;

function json(statusCode, body) {
  return {
    statusCode,
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify(body)
  };
}

async function getPass(key) {
  // Fase Lectura: consulta el evento y la inscripción.
  return json(501, { message: 'Lectura por construir' });
}

async function register(key) {
  // Fase Inscripción: crea un registro con una condición.
  return json(501, { message: 'Inscripción por construir' });
}

async function checkIn(key) {
  // Fase Entrada: actualiza una inscripción existente.
  return json(501, { message: 'Entrada por construir' });
}

export async function handler(event) {
  const { eventId, userId } = event.pathParameters ?? {};
  const method = event.requestContext?.http?.method;
  if (eventId !== 'evt-001' || !/^equipo-\d{2}$/.test(userId ?? '')) {
    return json(400, { message: 'Usa evt-001 y un código equipo-00 a equipo-99' });
  }

  const key = { eventId, userId };
  try {
    if (method === 'GET') return await getPass(key);
    if (method === 'POST') return await register(key);
    if (method === 'PATCH') return await checkIn(key);
    return json(405, { message: 'Método no permitido' });
  } catch (error) {
    if (error.name === 'ConditionalCheckFailedException') {
      return json(409, { message: 'La operación no se puede aplicar a este estado' });
    }
    console.error(error.name, error.message);
    return json(500, { message: 'Revisa los logs de la función' });
  }
}

stack="festival-checkin-${STUDENT_CODE}-dev"
salida() {
  aws cloudformation describe-stacks --stack-name "$stack" \
    --profile "$perfil" --region "$region" \
    --query "Stacks[0].Outputs[?OutputKey=='$1'].OutputValue | [0]" --output text
}
tabla_eventos=$(salida EventsTableName)

Espera y comprueba las claves

Ejecuta el bloque. wait vuelve al prompt sin imprimir nada cuando la tabla está lista. describe-table muestra las claves.

for tabla in "$tabla_eventos" "$tabla_inscripciones"; do
  aws dynamodb wait table-exists \
    --profile "$perfil" --region "$region" --table-name "$tabla" || break

Referencias de la práctica

Del modelo al primer registro

Relaciona el JSON con las tablas

Buscad DataModel. Ahí hay una definición por tabla. Dentro de cada una, buscad estas tres partes.

TableName
El nombre que veis encima de cada tabla.
KeyAttributes
Las claves que el visor marca como PK y SK. AttributeName es el nombre del campo y S significa texto. En Events, el nombre de SortKey está vacío porque esa tabla solo tiene PK.
TableData
Las filas ficticias. { "S": "evt-001" } guarda el texto evt-001. La vista de tabla muestra directamente ese valor.

NonKeyAttributes enumera campos como title y registeredAt. Para esta primera lectura podéis pasar por alto los metadatos, DataAccess y la lista vacía de índices.
