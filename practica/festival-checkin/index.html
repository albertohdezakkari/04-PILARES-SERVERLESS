Un evento

Una inscripción concreta

Dentro del grupo, USER_ID es la clave de ordenación (SK). La pareja EVENT_ID + USER_ID es la clave primaria compuesta.

INSCRIPCIONES → PK 1 + SK usuario-02 → una fila

Los eventos de un usuario

Guardas cada inscripción una vez. DynamoDB mantiene el índice PorUsuario, que agrupa esas inscripciones por USER_ID (PK) y las ordena por EVENT_ID (SK).

PorUsuario → PK usuario-02 → 1, 2

Convierte el modelo en tres tablas y pruébalo

Escribe los atributos de DynamoDB en mayúsculas con guion bajo, como EVENT_ID. Cuando la API recibe o devuelve JSON, usa nombres como eventId. Verás cómo traducirlos en Lectura.

Convención de Base de Datos. Llama a las entidades Evento, Inscripción y Usuario. Usa la abreviatura del proyecto, un guion bajo y el nombre de la tabla en plural. En Festival Check-in obtienes FCI_EVENTOS, FCI_INSCRIPCIONES y FCI_USUARIOS. «San Valentín» sería el título de un evento guardado en FCI_EVENTOS.

Evento → EVENTOS. Guarda EVENT_ID y TITLE. Inscripción → INSCRIPCIONES. Guarda la pareja de identificadores, y REGISTERED_AT.

EVENT_ID y USER_ID son referencias al evento y a la persona, como dos claves foráneas en un modelo relacional. La clave primaria de la inscripción es la pareja EVENT_ID + USER_ID, que garantiza una inscripción por persona y evento.

Usuario → USUARIOS. Guarda USER_ID, DISPLAY_NAME y CITY. Si Leo cambia de ciudad, actualiza su perfil una vez. Sus inscripciones conservan el mismo USER_ID.

En DynamoDB la aplicación decide qué referencias comprueba. En esta práctica, POST comprueba que el evento existe y acepta el código de usuario de la ruta. Consulta y edita los perfiles desde Sembrar datos → Usuarios.

Recupera el rol de Lambda

Quién actúa en cada momento. Tu perfil ejecuta el despliegue. El rol LabRole da permisos a Lambda cuando atiende una petición y necesita acceder a DynamoDB.

En Conectar → Comprobación verificaste tu perfil y tu región. El bloque conserva esos valores en la misma terminal. Si abriste otra, vuelve primero a Comprobación para seleccionar tu perfil y región.

AWS_PROFILE
Copia el nombre del perfil de $perfil. Las credenciales temporales están en el perfil que guardaste en ~/.aws/credentials.
AWS_REGION
Copia $region. Serverless usa ese valor en provider.region.
LAMBDA_ROLE_ARN
El comando aws iam get-role consulta el identificador del rol existente LabRole y lo guarda en esta variable.

Ejecuta el bloque desde la carpeta festival-checkin.

export AWS_PROFILE="$perfil"
export AWS_REGION="$region"
LAMBDA_ROLE_ARN=$(aws iam get-role --role-name LabRole --profile "$perfil" --region "$region" --query 'Role.Arn' --output text) &&
  export LAMBDA_ROLE_ARN &&
  printf 'AWS_PROFILE=%s\nAWS_REGION=%s\nLAMBDA_ROLE_ARN=%s\n' \
    "$AWS_PROFILE" "$AWS_REGION" "$LAMBDA_ROLE_ARN"

Si el laboratorio deniega iam:GetRole, consulta las instrucciones del laboratorio o solicita el ARN autorizado para tu cuenta. Escríbelo con export LAMBDA_ROLE_ARN="ARN_DEL_LAB", sustituyendo el valor entre comillas.

Cómo se comunica la web con API Gateway

httpApi:
Abre la configuración de la API HTTP de API Gateway, el servicio que recibe las peticiones de la web.
payload: '2.0'
Indica el formato que API Gateway usa para entregar la petición a Lambda. El código lee el método en event.requestContext.http.method. Las comillas hacen que YAML lea 2.0 como texto.
cors:
Agrupa las reglas que consulta el navegador cuando la web y la API están en orígenes distintos.
allowedOrigins:
Lista los orígenes web permitidos. El guion introduce https://albertohdezakkari.github.io como elemento de la lista.
allowedHeaders:
Lista las cabeceras admitidas desde el navegador. Content-Type indica el tipo de contenido enviado.
allowedMethods:
Lista los métodos que puede usar la web: GET para consultar el pase y POST para inscribirse. Cada guion añade un método.

Busca el guion delante de POST. Marca un elemento de la lista allowedMethods.

Por qué INSCRIPCIONES necesita dos valores

FestivalCheckInInscripciones:
Identificador lógico de las inscripciones de Festival Check-in. Usa Ref: FestivalCheckInInscripciones cuando necesites su nombre físico.
AttributeDefinitions:
Contiene dos elementos: EVENT_ID y USER_ID. EVENT_ID es numérico (N) y USER_ID es texto (S).
TableName:
Fija el nombre real en AWS, FCI_INSCRIPCIONES.
KeySchema:
Define la clave compuesta de la tabla. EVENT_ID agrupa las inscripciones y USER_ID distingue a cada usuario dentro del grupo.
KeyType: HASH
EVENT_ID es la clave de partición y permite agrupar las inscripciones por evento.
KeyType: RANGE
USER_ID es la clave de ordenación y distingue a cada usuario dentro del evento. (1, usuario-01) y (1, usuario-02) son dos claves completas distintas.

Declara los índices de FestivalCheckInInscripciones. Este índice añade otra forma de buscar las inscripciones de esa tabla.
IndexName:
Identifica el índice. Usa PorUsuario al hacer la consulta.
KeySchema:
Define las claves del índice. Usa el número EVENT_ID y el texto USER_ID ya declarados en AttributeDefinitions.
