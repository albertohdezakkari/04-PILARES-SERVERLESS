Conectar con AWS Academy

Abre el laboratorio

En AWS Academy, pulsa Learner Lab → Start Lab. Cuando esté activo, abre AWS Details → AWS CLI → Show. Ten ese bloque a mano.

En Git Bash (Windows) o Terminal (Mac), comprueba que tienes la herramienta.

aws --version

Si el comando no existe, abre la instalación de AWS CLI v2 y vuelve a abrir la terminal.

Antes de avanzar La terminal muestra una versión de AWS CLI y tienes el bloque de tu sesión.

Abre el archivo de credenciales

Elige el comando de tu sistema. Se abrirá un editor para el archivo credentials, fuera del repositorio.

mkdir -p ~/.aws

notepad.exe "$(cygpath -w ~/.aws/credentials)"
mkdir -p ~/.aws

Antes de avanzar Ves el archivo abierto en el Bloc de notas o en TextEdit.

Pega el bloque y guarda

Copia el bloque completo de AWS Details en el editor y guarda con Ctrl+S en Windows o ⌘S en Mac. Estas son las líneas que debes reconocer:

[default]
aws_access_key_id = VALOR_DE_LA_SESION
aws_secret_access_key = VALOR_DE_LA_SESION
aws_session_token = VALOR_DE_LA_SESION

Si ya usas [default] para otra cuenta, guarda el bloque del laboratorio con la cabecera [academy]. Si ya tienes un perfil del laboratorio, reemplaza sus tres valores juntos.

Antes de avanzar El archivo está guardado y sabes si tu cabecera es default o academy.

Comprueba identidad y región

Cambia perfil si has guardado [academy]. Sustituye us-east-1 por la región autorizada de tu laboratorio. Conserva esta terminal.

aws configure list-profiles
perfil=default
region=us-east-1
export AWS_PAGER=""
aws sts get-caller-identity --profile "$perfil" --region "$region"
aws dynamodb list-tables --profile "$perfil" --region "$region"

Si falla: si el perfil no existe, usa un nombre que aparezca en la lista. Si el token caducó, vuelve a AWS Details y copia los tres valores vigentes. Si STS funciona y DynamoDB da AccessDenied, revisad los permisos con el profesor.

Antes de avanzar STS devuelve la identidad y DynamoDB muestra TableNames. Puede estar vacía.

Dos tablas, un evento

¿Quién se ha inscrito y quién ha entrado?

Para encontrar a los inscritos, primero buscamos el evento. Para encontrar a una persona, añadimos su identificador.

Events
eventId · PK
1 ─── 0..N
Registrations
eventId · PK
userId · SK

Cargando el ejemplo…

En el ejemplo, checkedInAt indica que la persona ya entró. En AWS, la tabla de inscripciones empezará vacía.

Antes de avanzar Puedes explicar por qué las dos inscripciones tienen el mismo eventId y distinto userId.

Pon nombre a las tablas

Usa la misma terminal de Conexión y cambia equipo-01 por tu prefijo.

equipo=equipo-01
tabla_eventos="$equipo-events"
tabla_inscripciones="$equipo-registrations"
printf "%s\n" "$tabla_eventos" "$tabla_inscripciones"

Antes de avanzar Ves los dos nombres con tu prefijo. Los usarás también al configurar Lambda.

Crea Events con una sola clave

Un evento se encuentra con su eventId. En el comando, S indica texto y HASH marca la clave de partición.

aws dynamodb create-table \
  --profile "$perfil" --region "$region" \
  --table-name "$tabla_eventos" \
  --attribute-definitions AttributeName=eventId,AttributeType=S \
  --key-schema AttributeName=eventId,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST \
  --query 'TableDescription.TableStatus' --output text

Antes de avanzar La terminal responde CREATING o ACTIVE. Si la tabla ya existe, revisa sus claves en el paso Estado.

Crea Registrations con dos claves

eventId agrupa las inscripciones del evento. userId distingue a cada persona. RANGE marca la clave de ordenación.

aws dynamodb create-table \
  --profile "$perfil" --region "$region" \
  --table-name "$tabla_inscripciones" \
  --attribute-definitions AttributeName=eventId,AttributeType=S AttributeName=userId,AttributeType=S \
  --key-schema AttributeName=eventId,KeyType=HASH AttributeName=userId,KeyType=RANGE \
  --billing-mode PAY_PER_REQUEST \
  --query 'TableDescription.TableStatus' --output text

Antes de avanzar La terminal responde CREATING o ACTIVE.

Espera y comprueba las claves

Ejecuta el bloque. wait vuelve al prompt sin imprimir nada cuando la tabla está lista. describe-table muestra las claves.

for tabla in "$tabla_eventos" "$tabla_inscripciones"; do
  aws dynamodb wait table-exists \
    --profile "$perfil" --region "$region" --table-name "$tabla" || break
  aws dynamodb describe-table \
    --profile "$perfil" --region "$region" --table-name "$tabla" \
    --query 'Table.{Nombre:TableName,Estado:TableStatus,Claves:KeySchema}' || break
done

Antes de avanzar Ambas están ACTIVE. Events tiene eventId como HASH. Registrations añade userId como RANGE.

Guarda el primer evento

Usa PartiQL para guardar «Festival de otoño» con el identificador evt-001.

aws dynamodb execute-statement \
  --profile "$perfil" --region "$region" \
  --statement "INSERT INTO \"$tabla_eventos\" VALUE {'eventId': 'evt-001', 'title': 'Festival de otoño'}"

Antes de avanzar El comando vuelve al prompt sin error. Si ves DuplicateItemException, el evento ya existe y puedes comprobarlo en el siguiente paso.

Lee lo que se ha guardado

Ejecuta cada consulta y compara sus salidas.

aws dynamodb execute-statement \
  --profile "$perfil" --region "$region" --consistent-read \
  --statement "SELECT eventId, title FROM \"$tabla_eventos\" WHERE eventId = 'evt-001'"
aws dynamodb execute-statement \
  --profile "$perfil" --region "$region" --consistent-read \
  --statement "SELECT * FROM \"$tabla_inscripciones\" WHERE eventId = 'evt-001'"

Antes de avanzar Events devuelve evt-001 y Festival de otoño. Registrations devuelve Items: [] si aún no hay inscripciones.

Leer desde Lambda

Crea la función y elige las tablas

En la consola de la región del laboratorio, crea una función Lambda Node.js 22 con el rol de ejecución que indique el profesor. En Configuration → Environment variables, configura EVENTS_TABLE y REGISTRATIONS_TABLE con los dos nombres del paso Datos.

Antes de avanzar La función existe y las variables coinciden con los nombres de tus tablas.

Abre index.mjs y guarda el punto de partida

Copia el archivo completo en el editor de Lambda y pulsa Deploy. Los tres métodos están señalados para que los construyas en clase.

import { DynamoDBClient } from '@aws-sdk/client-dynamodb';
import {
  DynamoDBDocumentClient, GetCommand, PutCommand, UpdateCommand
} from '@aws-sdk/lib-dynamodb';

const db = DynamoDBDocumentClient.from(new DynamoDBClient({}));
const eventsTable = process.env.EVENTS_TABLE;
const registrationsTable = process.env.REGISTRATIONS_TABLE;

function json(statusCode, body) {
  return {
    statusCode,
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify(body)
  };
}

async function getPass(key) {
  // Fase Lectura: consulta el evento y la inscripción.
  return json(501, { message: 'Lectura por construir' });
}

async function register(key) {
  // Fase Inscripción: crea un registro con una condición.
  return json(501, { message: 'Inscripción por construir' });
}

async function checkIn(key) {
  // Fase Entrada: actualiza una inscripción existente.
  return json(501, { message: 'Entrada por construir' });
}

export async function handler(event) {
  const { eventId, userId } = event.pathParameters ?? {};
  const method = event.requestContext?.http?.method;
  if (eventId !== 'evt-001' || !/^equipo-\d{2}$/.test(userId ?? '')) {
    return json(400, { message: 'Usa evt-001 y un código equipo-00 a equipo-99' });
  }

  const key = { eventId, userId };
  try {
    if (method === 'GET') return await getPass(key);
    if (method === 'POST') return await register(key);
    if (method === 'PATCH') return await checkIn(key);
    return json(405, { message: 'Método no permitido' });
  } catch (error) {
    if (error.name === 'ConditionalCheckFailedException') {
      return json(409, { message: 'La operación no se puede aplicar a este estado' });
    }
    console.error(error.name, error.message);
    return json(500, { message: 'Revisa los logs de la función' });
  }
}

Referencias de la práctica

Del modelo al primer registro

Relaciona el JSON con las tablas

Buscad DataModel. Ahí hay una definición por tabla. Dentro de cada una, buscad estas tres partes.

TableName
El nombre que veis encima de cada tabla.
KeyAttributes
Las claves que el visor marca como PK y SK. AttributeName es el nombre del campo y S significa texto. En Events, el nombre de SortKey está vacío porque esa tabla solo tiene PK.
TableData
Las filas ficticias. { "S": "evt-001" } guarda el texto evt-001. La vista de tabla muestra directamente ese valor.

NonKeyAttributes enumera campos como title y registeredAt. Para esta primera lectura podéis pasar por alto los metadatos, DataAccess y la lista vacía de índices.

Prueba a cambiar Festival de otoño por otro título y pulsa Ver tablas. Cambiará la celda de Events en esta página.
