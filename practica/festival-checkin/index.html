El festival abre puertas

Construid una aplicación que permita consultar un evento, apuntarse y registrar la entrada. Trabajad por parejas y turnaos para escribir y comprobar.

Abrid la Pantalla de prueba en modo Ensayo. Pulsad Consultar, luego Registrar entrada. ¿Qué ocurre si la persona aún no se ha inscrito?

Lee serverless.yml línea a línea

Este archivo describe qué desplegar en AWS. Ábrelo por bloques y lee cada línea como una instrucción de configuración. Puedes seguir la explicación junto al código.

Cómo leer YAML. En name: aws, name es la clave y aws su valor. Si después de provider: hay líneas más a la derecha, esas líneas forman su bloque. Usa espacios para la sangría y alinea las claves del mismo nivel. Un guion al principio de una línea, como - GET, introduce un elemento de una lista.

Nombre, versión y destino del despliegue

service:
Nombre del servicio. festival-checkin- es nuestro prefijo. ${env:STUDENT_CODE} pide a Serverless el valor de la variable exportada en la terminal. Con equipo-01, el nombre queda festival-checkin-equipo-01.
frameworkVersion: ~4.45.0
Versión de Serverless Framework que admite el proyecto. ~ permite actualizaciones de parche de la serie 4.45, como 4.45.1.
provider:
Abre el bloque de configuración de la plataforma. Las líneas name, runtime, region, stage e iam están dentro de ese bloque.
name: aws
Selecciona Amazon Web Services como plataforma.
runtime: nodejs22.x
Indica con qué entorno ejecutará AWS el código de Lambda. Aquí se usa Node.js 22.
region: ${env:AWS_REGION}
Elige la región de AWS leyendo la variable de la terminal. Por ejemplo, us-east-1.
stage: dev
Nombra el entorno del servicio. dev es el nombre que elegimos para el entorno de desarrollo.
iam:
Abre el bloque de identidad y permisos de AWS.
role: ${env:LAMBDA_ROLE_ARN}
Indica qué rol del laboratorio usará Lambda. Un ARN identifica ese rol en AWS. Sus permisos determinan qué puede hacer la función, como leer o escribir en DynamoDB.

Cómo recibe Lambda los nombres de sus tablas

environment:
Agrupa las variables de entorno que Serverless configura para Lambda. En JavaScript se leen con process.env.
EVENTS_TABLE:
Nombre que elegimos para la variable que guarda el nombre de la tabla de eventos. El código la lee con process.env.EVENTS_TABLE.
REGISTRATIONS_TABLE:
Variable que elegimos para el nombre de la tabla de inscripciones.
Ref: EventsTable
Ref es una referencia de CloudFormation. EventsTable es el identificador que damos al recurso en Resources. Para una tabla DynamoDB, Ref devuelve el nombre real asignado en AWS. Ref: RegistrationsTable hace lo mismo con la otra tabla.

Cómo se comunica la web con API Gateway

httpApi:
Abre la configuración de la API HTTP de API Gateway, el servicio que recibe las peticiones de la web.
payload: '2.0'
Indica el formato que API Gateway usa para entregar la petición a Lambda. El código lee el método en event.requestContext.http.method. Las comillas hacen que YAML lea 2.0 como texto.
cors:
Agrupa las reglas que consulta el navegador cuando la web y la API están en orígenes distintos.
allowedOrigins:
Lista los orígenes web permitidos. El guion introduce https://albertohdezakkari.github.io como elemento de la lista.
allowedHeaders:
Lista las cabeceras admitidas desde el navegador. Content-Type indica el tipo de contenido enviado.
allowedMethods:
Lista los métodos que puede usar la web: GET para consultar el pase, POST para inscribirse y PATCH para registrar la entrada. Cada guion añade un método.

Busca el guion delante de PATCH. Marca un elemento de la lista allowedMethods.

Cómo una ruta llega a index.mjs

build:
Abre los ajustes de preparación del código para el despliegue.
esbuild: false
false es un valor booleano. Aquí desactiva la herramienta integrada esbuild porque desplegamos el JavaScript de index.mjs.
functions:
Agrupa las funciones Lambda del servicio.
checkin:
Es el nombre que le damos a nuestra función dentro del proyecto.
handler: index.handler
Une el nombre base del archivo index.mjs con el nombre de la función exportada handler. AWS llama a esa función cuando llega la petición.
events:
Lista lo que puede activar esa Lambda. Cada - httpApi: añade una ruta HTTP.
method:
Selecciona el método HTTP de la ruta. GET, POST y PATCH activan el mismo handler, que usa el método para elegir la operación.
path:
Define la dirección que se compara con la petición. En /events/evt-001/registrations/equipo-02, las llaves de la plantilla marcan los huecos: {eventId} recibe evt-001 y {userId} recibe equipo-02.

Cómo se crea EventsTable

resources: → Resources:
El primer bloque pertenece a Serverless Framework. Dentro, Resources, con mayúscula, lista los recursos que crea CloudFormation.
EventsTable:
Identificador lógico que elegimos para la tabla de eventos. Es el mismo que aparece en Ref: EventsTable.
Type: AWS::DynamoDB::Table
Indica a CloudFormation qué tipo de recurso debe crear: una tabla DynamoDB.
Properties:
Agrupa los ajustes de esa tabla.
BillingMode: PAY_PER_REQUEST
Selecciona el modo bajo demanda. Las lecturas y escrituras se cobran según el uso.
AttributeDefinitions:
Lista los atributos que forman las claves y su tipo. AttributeName: eventId da el nombre del atributo y AttributeType: S lo declara de tipo texto.
KeySchema:
Lista qué papel cumple cada atributo en la clave. AttributeName repite el nombre del atributo y KeyType: HASH lo declara clave de partición. En esta tabla, eventId basta para localizar evt-001.

¿Qué valor necesitas para buscar el evento Festival de otoño en EventsTable?

Por qué RegistrationsTable necesita dos valores

RegistrationsTable:
Identificador lógico de la tabla de inscripciones. Type, Properties y BillingMode tienen la misma función que en EventsTable.
AttributeDefinitions:
Contiene dos elementos: eventId y userId. El campo AttributeType: S indica que ambos valores son texto.
KeyType: HASH
eventId es la clave de partición y permite agrupar las inscripciones por evento.
KeyType: RANGE
userId es la clave de ordenación y distingue a cada equipo dentro del evento. (evt-001, equipo-01) y (evt-001, equipo-02) son dos claves completas distintas.

Si ya existe (evt-001, equipo-01), ¿puedes guardar (evt-001, equipo-02) como otra fila?

Qué devuelve el despliegue a la terminal

Outputs:
Declara los valores que CloudFormation muestra como resultado del despliegue. Está al mismo nivel que Resources.
EventsTableName:
Nombre que elegimos para la salida de la tabla de eventos. RegistrationsTableName es la salida de la otra tabla.
Value:
Indica qué dato devuelve cada salida. Con Ref: EventsTable, devuelve el nombre real de la tabla de eventos. Lo recuperarás desde la terminal en Salidas.

El handler recibe la petición y elige la operación. Por ahora cada operación responde 501 hasta que la construyas.

import { DynamoDBClient } from '@aws-sdk/client-dynamodb';
import {
  DynamoDBDocumentClient, GetCommand, PutCommand, UpdateCommand
} from '@aws-sdk/lib-dynamodb';

const db = DynamoDBDocumentClient.from(new DynamoDBClient({}));
const eventsTable = process.env.EVENTS_TABLE;
const registrationsTable = process.env.REGISTRATIONS_TABLE;

function json(statusCode, body) {
  return {
    statusCode,
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify(body)
  };
}

async function getPass(key) {
  // Fase Lectura: consulta el evento y la inscripción.
  return json(501, { message: 'Lectura por construir' });
}

async function register(key) {
  // Fase Inscripción: crea un registro con una condición.
  return json(501, { message: 'Inscripción por construir' });
}

async function checkIn(key) {
  // Fase Entrada: actualiza una inscripción existente.
  return json(501, { message: 'Entrada por construir' });
}

export async function handler(event) {
  const { eventId, userId } = event.pathParameters ?? {};
  const method = event.requestContext?.http?.method;
  if (eventId !== 'evt-001' || !/^equipo-\d{2}$/.test(userId ?? '')) {
    return json(400, { message: 'Usa evt-001 y un código equipo-00 a equipo-99' });
  }

  const key = { eventId, userId };
  try {
    if (method === 'GET') return await getPass(key);
    if (method === 'POST') return await register(key);
    if (method === 'PATCH') return await checkIn(key);
    return json(405, { message: 'Método no permitido' });
  } catch (error) {
    if (error.name === 'ConditionalCheckFailedException') {
      return json(409, { message: 'La operación no se puede aplicar a este estado' });
    }
    console.error(error.name, error.message);
    return json(500, { message: 'Revisa los logs de la función' });
  }
}

Relaciona el JSON con las tablas

Buscad DataModel. Ahí hay una definición por tabla. Dentro de cada una, buscad estas tres partes.

TableName
El nombre que veis encima de cada tabla.
KeyAttributes
Las claves que el visor marca como PK y SK. AttributeName es el nombre del campo y S significa texto. En Events, el nombre de SortKey está vacío porque esa tabla solo tiene PK.
TableData
Las filas ficticias. { "S": "evt-001" } guarda el texto evt-001. La vista de tabla muestra directamente ese valor.

NonKeyAttributes enumera campos como title y registeredAt. Para esta primera lectura podéis pasar por alto los metadatos, DataAccess y la lista vacía de índices.
