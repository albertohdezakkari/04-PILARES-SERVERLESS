Aplica las reglas

El service comprueba que el ID sea un entero positivo y que el título tenga texto. Cuando termina la escritura, devuelve ambos valores.

03 El service comprueba antes de guardar

service.mjs
if (typeof title !== 'string' || title.trim() === '') {
  throw new Error('Escribe un título para el evento');
}

await crearEventoRepository(eventId, title);

El || se lee «o». Si el título tiene otro tipo o al quitar los espacios queda vacío, throw detiene el alta. Con datos válidos, await espera a que termine la escritura.

src/eventos/crear-evento/service.mjs
import { crearEventoRepository } from './repository.mjs';

export async function crearEventoService(eventId, title) {
  if (!Number.isSafeInteger(eventId) || eventId < 1) {
    throw new Error('Indica un ID de evento entero positivo');
  }
  if (typeof title !== 'string' || title.trim() === '') {
    throw new Error('Escribe un título para el evento');
  }

  await crearEventoRepository(eventId, title);
  return { eventId, title };
}

Prepara la escritura

El repository prepara PutItemCommand con DynamoDB Toolbox. Solicita a DynamoDB que escriba solo si no existe un ítem con esa clave.

04 El repository prepara la escritura

repository.mjs
const comando = MODELO_EVENTO.build(PutItemCommand)
  .item(evento)
  .options({
    condition: { attr: 'eventId', exists: false }
  });

await comando.send();

.item(evento) adjunta la ficha. La condición pide que la clave esté libre. send() envía la operación a DynamoDB, donde se comprueba la condición.

Ver la línea en su archivo ↓

↓Toolbox usa el modelo para traducir los campos de la ficha antes de enviarla.

Localiza la condición que protege un evento existente.

src/eventos/crear-evento/repository.mjs
import { PutItemCommand } from 'dynamodb-toolbox/entity/actions/put';
import { MODELO_EVENTO } from '../models/evento.model.mjs';

export async function crearEventoRepository(eventId, title) {
  const evento = {
    eventId,
    title
  };

  const comando = MODELO_EVENTO.build(PutItemCommand)
    .item(evento)
    .options({
      condition: { attr: 'eventId', exists: false }
    });

  await comando.send();
}

Del objeto de JavaScript al ítem de DynamoDB

Sigue el evento 3. En el repository se llama eventId. En DynamoDB se guarda como EVENT_ID. El modelo describe esa traducción.

En JavaScript{ eventId: 3, title: 'Concierto de aula' }
→
En DynamoDB{ EVENT_ID: 3, TITLE: 'Concierto de aula' }

  1. 1. Reúne las herramientas

    Table y Entity vienen de Toolbox. item() agrupa los campos del esquema. number() y string() declaran tipos. Del proyecto importas db, el cliente que habla con AWS, y TABLA_EVENTOS_FCI, el nombre de la tabla configurado para Lambda.

    Ir a los imports ↓

  2. 2. Indica a qué tabla accedes

    Serverless crea la tabla al desplegar. new Table({...}) la representa en JavaScript. Dile su nombre con name, cómo conectarte con documentClient: db y cómo se identifica un ítem con partitionKey. En DynamoDB la clave se llama EVENT_ID y es numérica.

    Ir a la clave de la tabla ↓

  3. 3. Describe una ficha de evento

    new Entity({...}) define el modelo llamado Evento. table lo vincula con TABLA_MODELO_EVENTO. schema: item({...}) indica qué campos espera Toolbox y cómo guardarlos.

    number({ big: true })
    El ID es numérico y el modelo admite BigInt.
    .key()
    Marca eventId como parte de la clave en el objeto JavaScript.
    .savedAs('EVENT_ID')
    Une ese campo con la clave declarada en la tabla. El valor sigue siendo 3.

    title es un texto que se guarda como TITLE. La llamada que prepara la escritura está en el repository.

    Ir a la línea de eventId ↓
entityAttribute: false
Toolbox omite _et: "Evento" al guardar. La etiqueta sirve para distinguir modelos cuando comparten tabla. Aquí FCI_EVENTOS contiene eventos.
timestamps: false
Toolbox omite _ct y _md, las fechas automáticas de creación y última modificación. Las fechas que declares expresamente en un modelo, como REGISTERED_AT en las inscripciones, siguen siendo datos de la aplicación.

Con ambas opciones en false, el evento 3 se guarda con EVENT_ID y TITLE. Atributos internos de DynamoDB Toolbox

Antes de avanzar. Pulsa la línea 11 y encuentra la clave en DynamoDB. Luego pulsa la línea 20 y localiza el nombre que usa JavaScript y el método que los une.

src/eventos/models/evento.model.mjs
import { Entity } from 'dynamodb-toolbox/entity';
import { Table } from 'dynamodb-toolbox/table';
import { item } from 'dynamodb-toolbox/schema/item';
import { string } from 'dynamodb-toolbox/schema/string';
import { number } from 'dynamodb-toolbox/schema/number';
import { db, TABLA_EVENTOS_FCI } from '../../datos/dynamo.mjs';

const TABLA_MODELO_EVENTO = new Table({
  name: TABLA_EVENTOS_FCI,
  documentClient: db,
  partitionKey: { name: 'EVENT_ID', type: 'number' }
});

export const MODELO_EVENTO = new Entity({
  name: 'Evento',
  table: TABLA_MODELO_EVENTO,
  entityAttribute: false,
  timestamps: false,
  schema: item({
    eventId: number({ big: true }).key().savedAs('EVENT_ID'),
    title: string().savedAs('TITLE')
  })
});

06 Lees lo que quedó en DynamoDB

Ítem de ejemplo · salida de get-item
{
  "EVENT_ID": { "N": "3" },
  "TITLE": { "S": "Concierto de aula" }
}

get-item localiza el ítem por su clave. En la salida de AWS CLI, N identifica un número y S un texto. Si vuelves a enviar el mismo ID, la condición de escritura conserva el registro anterior.
