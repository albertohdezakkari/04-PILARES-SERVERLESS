# Festival Check-in

- Aplicar criterios de ingeniería de software profesional en las prácticas y proyectos. Organizar el código por dominio y caso de uso, con módulos de responsabilidad clara y nombres que permitan localizar el comportamiento desde su punto de entrada. Separar el transporte HTTP, las reglas de negocio y el acceso a datos cuando ayude a entender y modificar el código. Compartir la lógica que realmente se repite y mantener la estructura proporcionada al proyecto. Al enseñar una decisión de arquitectura, explicar qué cambio futuro facilita y comprobar el comportamiento por la ruta que utilizará el usuario.

- En Festival Check-in, desplegar toda la infraestructura de la aplicación con Serverless Framework desde `serverless.yml`: las dos tablas DynamoDB, las funciones Lambda y la HTTP API con sus rutas. Reutilizar el rol autorizado de AWS Academy. Usar AWS CLI para comprobar la sesión y los recursos, invocar la creación de los eventos de ejemplo y comprobar los datos con PartiQL. Guiar desde Git Bash en Windows y Terminal en macOS, con la infografía enlazada dentro del cuaderno.

- Para cada paso que cree, edite, compruebe o despliegue archivos o recursos, incluir los comandos completos para Git Bash en Windows y Terminal en macOS. En cada práctica, indicar desde qué carpeta se ejecutan los comandos, explicar cómo crear los directorios requeridos y comprobar que existen antes de crear archivos dentro. Al crear un archivo, mostrar primero el comando de creación y apertura en una caja copiable y después el contenido completo en otra caja copiable. Cada caja copia únicamente su contenido. Mostrar los ejemplos de código y las funciones completas en secciones visibles del paso, con su botón de copia. Mantener las pestañas para navegar entre pasos y archivos. Evitar los acordeones y desplegables para presentar estos contenidos.

- Escribir el cuaderno del alumnado en segunda persona, con pasos que pueda seguir por sí mismo. En «Antes de avanzar», indicar qué acción realizar o qué comprobar y el resultado observable (filas, salida del comando, estado en pantalla o campos concretos). Reservar las indicaciones sobre cómo explicar, proyectar o dirigir la clase para el guion docente privado. Antes de pedir que copie un archivo de configuración largo, guiar la lectura con ejemplos de la práctica y una comprobación que el alumno pueda resolver mirando el código.

- Nombrar las entidades del diagrama en singular y las tablas de DynamoDB en plural y mayúsculas. Usar el prefijo FESTIVAL_CHECK_IN y el sufijo numérico del equipo, separados con barra baja, como `FESTIVAL_CHECK_IN_EVENTOS_01` e `FESTIVAL_CHECK_IN_INSCRIPCIONES_01`.

- Festival Check-in cubre dos consultas sobre las mismas inscripciones. Para listar los usuarios de un evento, usar `Query` en la tabla `INSCRIPCIONES` con `eventId` como clave de partición y `userId` como clave de ordenación. Para listar los eventos de un usuario, usar `Query` en el índice global `PorUsuario` de esa tabla, con `userId` como clave de partición y `eventId` como clave de ordenación. El cuaderno muestra ambas en Diseñar y las ejecuta en Validar → Consultar índice.

- La edición numérica de Festival Check-in usa `eventId` de tipo `N` en las dos tablas y conserva `userId` como texto. La Lambda `crearEvento`, invocada con AWS CLI, asigna identificadores positivos mediante el contador atómico del ítem reservado `eventId: 0` en EVENTOS. Las tablas de esta edición, por ejemplo `FESTIVAL_CHECK_IN_EVENTOS_01` e `FESTIVAL_CHECK_IN_INSCRIPCIONES_01`, se despliegan en un stack nuevo para conservar las tablas de las ediciones anteriores.
